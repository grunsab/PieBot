# Persistent Lazy SMP — 2026-09-29

The local engine now keeps all configured search threads busy throughout iterative deepening. Persistent helper searches share the transposition table and immutable NNUE weights, retain private histories and accumulators, and stop when the main search finishes. The main search chooses the reported move. This replaces root splitting, which left helpers idle during the first root move and repeatedly copied search state.

## Measured performance

Same Mac, model `lc0_chunk_00034965.nnue`, blend 75, Hash 256 MiB, eight threads, 1,000 ms requested per search. Eighteen positions, two repetitions each, alternating baseline/candidate order, one search at a time.

| Metric | Previous root splitting | Persistent Lazy SMP |
| --- | ---: | ---: |
| Aggregate nodes/second | 1,956,398 | 7,637,318 |
| Average CPU cores busy | 2.018 | 7.609 |
| Mean completed depth | 16.47 | 16.86 |

Aggregate throughput improved **3.90× over the previous eight-thread implementation**. Counts include helper nodes and redundant work; this is not a 3.90× increase in useful search or a measured Elo gain. The main thread completed 0.39 more plies on average in this short sample.

## Current build: one versus eight threads

A subsequent side-by-side UCI comparison on the rebuilt engine used the same 18 positions, two repetitions and 1,000 ms request. The broad test runner was paused throughout the timed trials and resumed afterwards.

| Metric | One thread | Eight threads |
| --- | ---: | ---: |
| Average completed depth | 14.94 plies | 16.69 plies |
| Aggregate nodes/second | 1,010,579 | 7,284,815 |
| Mean elapsed search time | 0.743 s | 0.796 s |

Eight threads delivered **1.75 additional plies** and **7.21× aggregate throughput**. These are matched time-budget searches: the existing time manager sometimes finishes before the requested second. The throughput figure includes redundant helper work and does not establish Elo. Raw results and reproduction script: `depth_1v8.json` and `depth_1v8.py` beside this report.

## Correctness and protocol checks

- All 18 one-thread depth-eight signatures matched the old engine exactly: moves, scores, nodes and depths.
- Both baseline and candidate passed all 91 mate-in-three positions at depth seven with one thread. The promoted engine also passed all 91 with eight threads, with no fallback moves.
- Seven new SMP regression tests passed, covering deterministic requests, global node limits, worker reuse, thread counts, helper shutdown, restarting/resizing, and state resets.
- Sixteen existing search-core regressions passed, including NNUE accumulator integrity, special moves, draw rules and interrupted iterations.
- All 412 NNUE-training Python tests and 142 script tests passed.
- The final UCI binary passed an eight-thread search while `RAYON_NUM_THREADS=1`: 7.50 average busy cores, 7,173,727 nodes. Stop latency was 6.9 ms; a 5,000-node request used exactly 5,000 nodes; a subsequent two-thread search returned a legal move.
- Full default and all-feature Rust batteries passed: 251 default tests and 241 all-feature tests across 72 test/benchmark executables per configuration. Local Gatekeeper/XProtect scans delayed startup; no protections were changed. One optional-backend UCI stop check failed initially and passed unchanged on retry; both attempts are preserved in the validation evidence.

Deterministic searches, explicit node budgets and the development dense-f32 NNUE backend use a single search thread. The normal quantized NNUE path uses the requested number of threads without a global Rayon environment setting.

## Completed game comparison — September 30

The current Lazy SMP engine played 100 games at each thread setting against Stockfish 18 at nominal `UCI_Elo=3190`, with 60+0.5 clocks and 50 matched openings played with reversed colors. One thread scored 1 win, 60 draws and 39 losses (31.0%); eight threads scored 5 wins, 71 draws and 24 losses (40.5%). The measured eight-minus-one-thread gain is **+72.2 Elo, joint paired-bootstrap 95% interval [+26.3, +119.4]**. The interval supports an eight-thread gain in this experiment. All 200 games passed replay and plan verification, with no technical forfeits.

This comparison uses the new implementation in both arms; it does not establish a game-level improvement over the old eight-thread implementation. The 3190 setting is nominal UCI strength, not a published CCRL rating. Full report and unmodified records: [thread comparison](thread_anchor_20260929/REPORT.md) in `evidence/`. Full Rust validation logs and the original failing/retried optional-backend stop check are preserved in that report's evidence bundle.
